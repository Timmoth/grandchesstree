# site

The static website for [grandchesstree.com](https://grandchesstree.com/).
Tailwind via CDN; everything else is hand-written HTML + vanilla JS. There's
one small build step (`build.js`) that:

1. Inlines a shared header + footer template into every page (so navigation
   lives in one place, not eleven).
2. Renders the leaderboard page from `src/assets/data/leaderboard.json`
   (cards, table, badge, and timestamp).
3. Copies static assets into `dist/`.
4. Calls `src/articles/build-articles.js` to publish the move-generation
   article series under `dist/move-generator/`.

## Layout

```
Site/
├── build.js               orchestrator (Node, no deps)
├── src/                   authoring source — what you edit
│   ├── *.html             page sources (header/footer get replaced at build)
│   ├── templates/         shared chrome
│   │   ├── header.html        the sticky top nav (active link via {{NAV_*}} vars)
│   │   └── footer.html        the site footer
│   ├── articles/          move-generation series + its publisher
│   │   ├── 01-introduction.md … 07-legal-move-generation.md
│   │   ├── build-articles.js   md → html, output to dist/move-generator/
│   │   ├── render-board.js     FEN/bitboard → PNG (for article figures)
│   │   ├── img/                figures
│   │   └── MoveGen/            reference C# move generator (own README)
│   ├── assets/            everything else, organised by kind
│   │   ├── js/                  movegen.js, movegen-wasm.js, board-export.js
│   │   ├── img/                 github-mark.svg + pieces/*.png (the chess piece PNGs)
│   │   └── data/                perft result JSON (studied-position data)
│   ├── results/           raw perft data (own README)
│   ├── robots.txt
│   └── sitemap.xml
├── dist/                  built output — what gets deployed
│   ├── *.html             top-level pages with chrome inlined
│   ├── assets/            copied verbatim from src/
│   ├── move-generator/    generated by src/articles/build-articles.js
│   └── wasm/movegen/      ← populated externally by
│                            src/articles/MoveGen/MoveGen.Wasm/publish-to-webapp.sh
└── README.md              ← this file
```

## Building

```sh
node build.js                  # full build (pages + assets + articles)
node build.js --skip-articles  # skip the article re-render for faster iteration
```

The build:
- Wipes everything in `dist/` **except** `dist/wasm/movegen/` (which is
  managed independently — the .NET WASM AOT publish is far too slow to run on
  every site rebuild).
- Detects the active nav section by inspecting each source page's existing
  `class="text-slate-900"` marker, then inlines the templated header with
  the right link highlighted.

To regenerate the WASM bundle (after editing the C# move generator):

```sh
cd src/articles/MoveGen/MoveGen.Wasm
./publish-to-webapp.sh
```

That writes directly into `Site/dist/wasm/movegen/`. No site rebuild needed.

## Editing pages

- **Regular page** (e.g. `tools.html`): edit `src/tools.html`. Build
  replaces `<header>` / `<footer>` blocks with the shared templates. The
  build infers active-nav from the existing `class="text-slate-900"` marker
  on the page's nav link.
- **Site chrome**: edit `src/templates/header.html` / `footer.html`.
- **New nav section**: add to `NAV_SECTIONS` in `build.js`, add a
  `{{NAV_NEW_NAME}}` slot to header/footer, and an `<li>` to both.
- **Article content**: edit markdown in `src/articles/`; run a full build.

## Local development

```sh
cd Site
node build.js
python3 -m http.server -d dist 8765
# then open http://localhost:8765/
```

Any small static server works (`npx serve dist`, `caddy file-server`, …).

## Deployment

`dist/` is the deployable artefact. Push its contents to whichever host
serves grandchesstree.com. There's no runtime build step.

If you commit `dist/`, the host just pulls. If you keep `dist/` gitignored
(see project-wide `.gitignore` for current policy), CI / deploy needs to
run `node build.js` first.

## JavaScript assets (under `src/assets/js/`)

- **`movegen.js`** — vanilla-JS move generator (BigInt bitboards). Mirrors
  `src/articles/MoveGen/MoveGen.App/`. Always-available fallback for the WASM engine.
- **`movegen-wasm.js`** — loader for the .NET WASM engine served from
  `dist/wasm/movegen/`. ~20× faster than the JS port.
- **`board-export.js`** — SVG board → pixel-art PNG. Drives "Save PNG".
- **`leaderboard.js`** — drives the "Drill down by run" section on
  `leaderboard.html`: dropdowns, stats grid, host card, NPS/CPU/RSS chart,
  per-depth table, click-to-sort headers. Reads
  `assets/data/leaderboard.json`.

## Images (under `src/assets/img/`)

- `github-mark.svg` — used by the header nav.
- `pieces/*.png` — the 12 chess piece PNGs (white/black × pawn, knight,
  bishop, rook, queen, king). Referenced by every board-rendering page
  (`fen-visualizer`, `bitboard-inspector`, `pgn-viewer`) and by
  `articles/render-board.js` when generating article figures.

## Data (under `src/assets/data/`)

- `perft_p{0,1,2}_results.json` — historical perft result data for the three
  studied positions (startpos / kiwipete / sje). Replace the JSON file to
  update the data; no page edits needed.
- `leaderboard.json` — the engine leaderboard for `leaderboard.html`. Same
  schema as the file emitted by `../Leaderboard/perft_war.py aggregate`. To
  refresh the leaderboard:

  ```sh
  cp ../Leaderboard/results/leaderboard.json src/assets/data/leaderboard.json
  node build.js --skip-articles
  ```

  The build reads it and renders the best-in-mode cards, the full results
  table, the engine count badge, and the "last benchmarked" timestamp.
  Unknown engines render as plain text in the table — add the engine name
  to `LB_KNOWN_ENGINES` in `build.js` to get a repo link.

## Article syntax highlighting

Article code blocks use [Prism.js](https://prismjs.com/) via the
jsDelivr CDN — included in the `<head>` of every generated article page.
The autoloader fetches language definitions on demand (`csharp`, `bash`,
`json`, etc.), so no static config needed for new languages. Theme:
`prism-tomorrow`, layered on top of our existing `bg-slate-900` containers.
